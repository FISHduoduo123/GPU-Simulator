# 分支/收敛单元（BRU）—— GPU 模拟器
> 汇总 4 个线程核心的分支请求，判条件，管理收敛栈/调用栈，输出新 PC、跳转请求与 4 核使能。

- 模块：warp 级 / 分支与收敛
- 状态：端口/接口与逻辑已确认并实现（`src/bru.rs`）；收敛栈/调用栈**溢出信号暂留**；待确认仅剩 `bru_en`/`bru_jump_req` 生效时序
- 更新日期：2026-11-26
- 依据：用户规定（4 组核心输入 + 16bit 地址输出 + 1bit 跳转请求 + 4 使能输出；4 核共享 PC；PC +2；BRA 双属性；BRAF 三状态收敛栈）+ 指令集流控段
- 关联：`docs/core/thread_core_spec.md`、`docs/warp/pc_spec.md`、`docs/warp/warp_spec.md`

## 1. 概述
BRU 负责：
1. 收集 4 个核心的分支端口；
2. 用各核心的计算标志判定 `br_cond`；
3. 按状态机维护收敛栈 / 调用栈；
4. 输出 `bru_jump_addr`、`bru_jump_req`、`bru_en[3:0]`。

## 2. 端口与接口
### 2.1 输入（BRU 视角；4 组，每组 7 信号）
| 端口 | 位宽 | 说明 |
|---|---|---|
| `br_jump_addr` | 16bit | 跳转目标地址（核心算好后送入） |
| `br_op` | 4bit | 流控 op |
| `br_cond` | 4bit | 条件编码 0..15（BRU 结合 `br_flags` 判定） |
| `br_uncond_attr` | 1bit | BRA 的 0/1 属性位 |
| `br_func` | 1bit | 流控子类型（CALL/RET、BRAP/REA） |
| `br_flags` | 16bit | 该核心计算标志（低 10 整数 + 高 6 浮点） |
| `br_mask` | 1bit | 掩码寄存器当前值 |

> 方向以 BRU 为视角：上述均为**输入**（在核心侧为核心输出）。

### 2.2 输出
| 端口 | 位宽 | 说明 |
|---|---|---|
| `bru_jump_addr` | 16bit | 仲裁后的新 PC（给 PC/取指） |
| `bru_jump_req` | 1bit | 跳转请求（给 PC） |
| `bru_en` | 4bit | 4 核使能（给各核心） |

> **时序**：`bru_en`/`bru_jump_req`/`bru_jump_addr` 均为**本周期组合直接输出**；核心的使能端口是**寄存器**，在**下一周期锁存**该使能；PC 在**下一周期直接置为新值**。

### 2.3 编码
**`br_op`**
| 值 | 含义 |
|---|---|
| `0000` | 无分支（默认） |
| `0110` | BRA |
| `0111` | BRAF |
| `1000` | BRAP / REA（func 区分：0=BRAP，1=REA） |
| `1001` | CALL / RET（func 区分：0=CALL，1=RET） |

> 无请求有效信号：BRU 以 `br_op != 0000` 判断本拍有无分支请求。

**`br_func`**：CALL/RET 的 0/1；BRAP/REA 的 0/1；BRA/BRAF 置 0。

**`br_cond`**：整数 `0000–1001`（EQ/NE/LT/GT/LE/GE/ULT/UGT/ULE/UGE）；浮点 `1010–1111`（FEQ/FNE/FLT/FGT/FLE/FGE）。核心只送编码，**不自行判断**。

**`br_uncond_attr`**：`0`=普通无条件；`1`=带收敛属性。仅 BRA 有意义，其余置 0。

**`br_jump_addr`**：16bit；BRA/BRAF 来自指令字段（`I[19:4]`），BRAP=入口地址，CALL=调用地址，RET/REA 由栈/使能逻辑处理。

## 3. 功能与行为
### 3.1 前提
- 4 核共用一个 PC，正常同地址执行；PC 顺延恒 **+2**。
- **4 核锁步**：同一拍执行同一条指令，故各核分支请求天然同 `br_op`/同目标；BRU 只把它当作**一个请求**处理，**不做优先级仲裁**，并行判断各使能核心是否满足条件。
- 分支指令才驱动 BRU；其余 op 时 BRU 无动作（PC 由 PC 模块 +2）。

### 3.2 BRA（op=0110）
| func | 属性 | 处理 |
|---|---|---|
| 0 | 普通 | `bru_jump_req=1`、`bru_jump_addr=目标` → PC=目标 |
| 1 | 收敛 | 见 §3.2.1 |

#### 3.2.1 收敛点（func=1）
- **路径 1 状态**遇到：① BRU 状态置 **2**；② 改栈顶状态字段为路径 2；③ PC=栈中 16bit 地址；④ 把本条跳转地址写入栈、替换栈顶 16bit 地址字段。
- **路径 2 状态**遇到：① PC=栈中地址；② 弹栈；③ 状态=新栈顶状态（无栈块→普通）；④ 用弹出条目的 `mask4` 设置 `bru_en`（恢复未满足子集）。**不做任何地址比较**。

### 3.3 BRAF（op=0111）三状态收敛
状态：0 普通 / 1 路径 1 / 2 路径 2。

处理：
1. 用 `br_cond` 与各核心 `br_flags` 比对；**仅 `bru_en[k]=1` 的核心参与**（未使能核心不参与、不影响分类）。
2. 记录满足/不满足数，相对“当前使能核心集”分类：
   - **混合**：压栈（条目 = `1bit 路径 | 4bit 掩码 | 16bit 返回地址`）：
     - 1bit = 固定 **1**（混合压栈时栈内路径恒为 1）；
     - 4bit = **`~满足 & 使能`**（仍使能但未满足的线程）；
     - 16bit = 当前指令的下一条地址（`pc+2`）。
     
     然后：`bru_en` 只使能满足线程 → 转路径 1 → PC=满足分支的跳转地址。
   - **仅满足**：PC=跳转地址。
   - **仅不满足**：不设 PC。
3. 路径 1/2 状态下的分类规则与普通状态相同。

### 3.4 CALL / RET（op=1001）
- 独立**调用栈**：深度 16、每项 16bit。
- **CALL**（func=0）：压 `PC+2` 入调用栈，同时 PC=目标地址。
- **RET**（func=1）：弹栈 → PC。
- **对使能/收敛状态无影响**：不改变 `bru_en`，也不改变 BRU 状态/收敛栈。
- **与 r15 数据栈、PUSH/POP 完全独立**：调用栈只存返回 PC，不读写数据栈。
- **调用栈溢出信号：暂留**（预留，本期不实现）；**RET 下溢忽略、PC 照常 `+2`**（不跳转）。

### 3.5 BRAP / REA（op=1000）
- **BRAP**（func=0）：读各核 `br_mask`，掩码=1 → 关闭该核使能（`bru_en[k]=0`）；掩码=0 保持使能；然后 PC=BRAP 入口地址。
  - 掩码写入来源：`MOV type=0111`（`mask ← reg[0]`）。
- **REA**（func=1）：`bru_en=4'b1111`（全使能），**不设 PC**（顺延）。

### 3.6 综合流程
1. 读 4 组 `br_op`。
2. 按 op 分派：`0000` 无动作；`0110` §3.2；`0111` §3.3；`1001` §3.4；`1000` §3.5。
3. 汇总：有可取跳转 → `bru_jump_req=1` + 目标；否则 req=0，PC+2。

### 3.7 状态小结
- 收敛栈：语义已定（不做比较）；弹栈时用栈顶 `mask4` 设置 `bru_en`；**溢出信号暂留**。
- 调用栈：CALL/RET 已定（与 r15 数据栈完全独立、下溢忽略并 +2）；**溢出信号暂留**。
- 同拍 4 核请求视为**一个请求**（锁步天然同 op/同目标），不做仲裁。
- `bru_en[k]` 语义：**只控制该核执不执行**。
- **生效时序（已定）**：BRU 本周期组合直接输出 `bru_en`/`bru_jump_req`/`bru_jump_addr`；核心使能端口为寄存器、下一周期锁存使能；PC 下一周期直接置新值。
