# 内存模块（测试阶段）规格书 —— GPU 模拟器

- 项目：GPU 模拟器
- 模块：测试阶段用内存模块（当前阶段验证用）
- 状态：**接口与行为已确认；实现代码待用户明确说“写代码”后才编写**
- 更新日期：2026-11-25
- 依据：用户本轮规定（64KB / 粒度 16bit / 4 组读写接口 + 1 读接口 / 字节使能小端）

---

## 1. 概述（已确认）
- **容量**：64KB（= 2^16 字节）。
- **寻址**：16bit **字节地址**，地址空间 0x0000..0xFFFF。
- **数据**：写 / 读数据均为 **32bit**。
- 结构化访问：一个 32bit 数据横跨 **2 个 16bit 地址单元 = 4 个字节**（地址 X 起，长度 4 字节）。
- **4 组读写接口**（⇔ 4 核心各一组）+ **1 个读接口**（⇔ 共享取指通道，接全局 PC）。

## 2. 每核心读写接口（k=0..3）

| 端口 | 方向 | 位宽 | 说明 |
|---|---|---|---|
| `addr_k` | 输入 | 16bit | 字节地址（本次访问首地址 X） |
| `wdata_k` | 输入 | 32bit | 写数据 |
| `be_k` | 输入 | 2bit | 字节使能（小端，见 §3） |
| `rw_k` | 输入 | 1bit | 读写控制：0=读，1=写 |
| `rdata_k` | 输出 | 32bit | 读数据 |

- 每组接口为**单条读写方向信号** `rw_k`（读/写二选一），非独立 ren/wen。

## 3. 字节使能（be[1:0]，小端模式，读写均生效）
- 低 16 位 `wdata_k[15:0]` ↔ **当前**地址单元（字节 X、X+1）。
- 高 16 位 `wdata_k[31:16]` ↔ **+1** 地址单元（字节 X+2、X+3）。
- `be_k` **写**编码（逐个 16bit 单元使能）：
  | `be_k` | 动作 |
  |---|---|
  | `11` | **当前与 +1 都写**：`wdata[15:0]`→[X,X+1] 且 `wdata[31:16]`→[X+2,X+3] |
  | `10` | **只写 +1**：`wdata[31:16]`→[X+2,X+3] |
  | `01` | **只写当前**：`wdata[15:0]`→[X,X+1] |
  | `00` | 无写入。（保留） |
- `be_k` **读**编码（按使能门控读数据，未使能的半字读为 0）：
  | `be_k` | 读结果 `rdata_k` |
  |---|---|
  | `11` | 读**全 32bit**：低 16 位=[X,X+1] 字，高 16 位=[X+2,X+3] 字 |
  | `10` | **低 16 位为 0**；高 16 位=[X+2,X+3] 字 |
  | `01` | **高 16 位为 0**；低 16 位=[X,X+1] 字 |
  | `00` | 全 0 |
- 小端（字节序）：字节 X=低字节、X+1=高字节（低 16 位字）；字节 X+2=低字节、X+3=高字节（高 16 位字）。

## 4. 读写行为
- **写**（`rw_k=1`）：按 §3 的 `be_k` 逐 16bit 单元写入；未使能的字节保持原值不变。
- **读**（`rw_k=0`）：`rdata_k` 按 §3 读编码 `be_k` 门控输出（未使能的半字为 0）。

## 5. 读接口（共享取指通道）

| 端口 | 方向 | 位宽 | 说明 |
|---|---|---|---|
| `f_ren` | 输入 | 1bit | 读信号（取指使能） |
| `f_addr` | 输入 | 16bit | 取指字节地址（≙ `g_raddr`= {0, PC}） |
| `f_rdata` | 输出 | 32bit | 取指数据（送 4 核指令端口广播） |

- 与 `docs/memory/mem_interface_spec.md` 的共享取指通道对应：`f_ren=g_rren`、`f_addr=g_raddr[15:0]`、`f_rdata=g_rdata`（32bit）；通过 `addr_in`（全局 PC）驱动。
- `f_rdata` **同时广播**到 4 个核心的指令端口（**指令端口为 24bit**，连线取 `f_rdata` 的上 24 位 `f_rdata[31:8]`，即 `instr = f_rdata >> 8`）。
- **取指读接口 `be` 常 `11`**：读回 32bit（指令为 24bit，位于其高 24 位，最低字节为 0、不打包）。

## 5.1 系统接线约定（已确认）
- **核心侧 4 组读写接口的字节使能 `be_k` 恒接 `01`**：核心以 16bit 数据访问，只用内存的**低 16 位**（`wdata[15:0]` ↔ 字节 X、X+1），高 16 位读回为 0、写时保持不变。
- **取指读接口 `be` 恒接 `11`**：完整读回 32bit，核心取上 24 位（`f_rdata[31:8]`）。

## 5.2 指令在内存中的存放（已确认）
- 指令为 **24 位** `I`：`op=I[23:20]`（最高 4 位）+ 5 个 4bit 字段 `f1=I[19:16]`、`f2=I[15:12]`、`f3=I[11:8]`、`f4=I[7:4]`、`f5=I[3:0]`（依据 `refs/GPU指令集.xlsx`，C..H 六列各 4bit）。
- 指令跨两个 16bit 单元存放（取指读接口 `be=11` 一次读 4 字节恢复指令，广播给 4 核）：
  - **+1 单元（字节 X+2、X+3）**：放指令**高 16 位 `I[23:8]`**，`op=I[23:20]` 位于该单元最高半字节。
  - **当前单元（字节 X、X+1）**：指令**低 8 位 `I[7:0]` 放在该单元【高 8 位】**（字节 X+1）；**低 8 位（字节 X）置 0**（不打包）。
- 单元内字节序（待确认）：+1 单元暂按小端（字节 X+2=`I[15:8]`、X+3=`I[23:16]`，`op` 在字节 X+3 高半字节）记录。

## 6. 边界与悬置项（不猜测）
- **对齐**：取指一次读 4 字节（两个 16bit 单元），要求 `addr` 对齐到 4 字节；非对齐行为待用户说明。
- **指令 `+1` 单元内的字节序**（字节 X+2/X+3 与 `I[23:8]` 的映射）—— 暂按小端记录，待确认。
- **PC 步长一致性**：取指读 4 字节/一条 24bit 指令，而 PC 递增为 +2 —— 与 16bit 字地址口径的换算待确认（PC 地址空间 16bit vs 数据字节地址 16bit 的对应）。
- **24 位指令 vs 现有 32 位解码假设**：本规格已定指令为 24 位（`op=I[23:20]`+5×4bit 字段）；但 `src/thread_core.rs`、`src/bru.rs` 当前按 32 位高位对齐（`op=I[31:28]`、`fld` 位移 `28-4n`）解码，需待用户说「写代码」时统一重排为 24 位。
- 冲突仲裁：4 组读写接口同拍同地址的写读/写写顺序 —— 待协议展开。
- 存储介质：按字节 `Vec<u8>`（64KB）还是按 16bit/32bit 字 —— 实现时定。
