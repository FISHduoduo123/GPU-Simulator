# 内存接口（Memory Interface）规格书 —— GPU 模拟器

- 项目：GPU 模拟器
- 模块：线程核心 ↔ 外部存储/访存通道
- 状态：**接口端口已确认（4 核心一对一）；实现代码待用户明确说“写代码”后才编写**
- 更新日期：2026-11-25
- 依据：用户本轮规定（四地址端口 + 四组读写控制，一一对应 4 核心）+ `docs/core/thread_core_spec.md` §5

---

## 1. 接口模型（已确认）
- **4 核心一对一 + 全局共享副读通道**：
  - 4 个线程核心各拥有一个独立访存端口组 `k`（k=0..3），组内信号互不共享。
  - 另有一条**全局共享的副读通道**（不归属任何核心），独立于 4 组端口。
- **指令广播**：副读通道返回的指令 `g_rdata` **同时（广播）送 4 个核心的指令端口**，4 核同拍执行同一条指令（SIMT 锁步）。
- 每个端口组 = **地址端口 + 读写控制端口 + 写数据输入 + 读数据输出**。
- 数据通路：
  - **4× 写数据输入（核心 → 内存）**，各 **32bit**。
  - **4× 读数据输出（内存 → 核心）**，各 **32bit**。
  - **1× 全局副读数据输出**，**32bit**（经副地址/副读信号驱动）。
- 响应时序：**单周期、无握手**（组合读写当拍返回/生效）。

## 2. 端口清单

### 2.1 每核心端口组 k（k=0..3）

| 端口名 | 方向 | 位宽 | 说明 |
|---|---|---|---|
| `addr_k` | 输出 | 17bit | 访存地址 |
| `wdata_k` | 输入（到内存） | **32bit** | 写数据（核心 → 内存） |
| `rdata_k` | 输出（来自内存） | **32bit** | 主读数据（内存 → 核心） |
| `ren_k` | 输出 | 1bit | 读使能（独立信号） |
| `wen_k` | 输出 | 1bit | 写使能（独立信号） |

### 2.2 全局副读通道（共享，不按核心分组）

| 端口名 | 方向 | 位宽 | 说明 |
|---|---|---|---|
| `addr_in` | 输入 | **16bit** | 全局地址输入（接全局 PC 的 `pc` 输出） |
| `g_raddr` | 输出 | 17bit | 副读地址（取指地址） |
| `g_rren` | 输出 | 1bit | 副读信号（=读使能） |
| `g_rdata` | 输出（来自内存） | **32bit** | 副读数据（内存 → 外部） |

- **`g_raddr` 由 `addr_in` 驱动**：`g_raddr = {0, addr_in}`（16bit 扩展为 17bit，高位补 0），充当共享取指通道的取指地址源。
- **请求有效**（第 k 组）= `ren_k \| wen_k`；任一为 1 即本拍该核心有访存请求。
- **副读通道有效** = `g_rren`。
- 读、写为**独立两信号**（`ren_k`/`wen_k`），不使用单一读写方向位。
- **原子信号不纳入本接口**（用户本轮规定控制端口仅 ren/wen；原子操作后续详细讨论再展开，见 §6）。
- **分支输出 `branch_out` 已从访存接口移除**：分支信息改由核心的分支端口经 BRU 处理（见 `docs/warp/branch_interface_spec.md`）。

## 3. 访存请求语义（每核心 + 副读通道）
- **读**（LDR/POP 等）：`ren_k=1`，`addr_k=地址`，读结果当拍经 `rdata_k` 返回核心并回写目的寄存器。
- **写**（STR/PUSH 等）：`wen_k=1`，`addr_k=地址`，写数据经 `wdata_k` 送往内存。
- **副读（取指）**：`g_rren=1` 时按 `g_raddr`（由 `addr_in` 扩展而来）经 `g_rdata` 返回指令，**同时广播（fan-out）送到 4 个核心的指令端口**（4 核同拍收到同一条指令）。

## 4. 与指令的对应
- op=`1010` 访存段：`0000 STR / 0001 LDR / 0010 PUSH / 0011 POP / 0100 ATADD / 0101 ATSWAP / 0110 ATCAS`。
- 地址来源（如 `rx(a)+rx(off)`）与栈（r15）语义在**访存协议**展开时定义。
- PUSH/POP 使用栈基址寄存器 r15，地址由栈指针计算，仍走本接口。

## 5. 顶层装配位置
- 端口组 k 由 `ThreadCore.k` 提供：
  - `addr_k = mem.addr`、`wdata_k = mem.wdata`、`ren_k = mem.is_read`、`wen_k = mem.is_write`（对应 `docs/core/thread_core_spec.md` 访存请求骨架）。
  - `rdata_k` 经 `ThreadCore.apply_load` 同拍回写读目的寄存器。
  - **注**：本规格 `wdata_k`/`rdata_k` 已改 **32bit**，但当前 `ThreadCore` 访存数据为 16bit —— 需在后续写代码时把核心侧数据通路加宽到 32bit（对齐规格）。
- **全局副读通道（预留 = 共享指令取指通道）**：
  - `addr_in` 由**全局 PC 的 `pc`（16bit）**经接线提供；
  - `g_raddr = {0, addr_in}`（扩展为 17bit）作取指地址；`g_rren` 为取指读使能；
  - `g_rdata` 返回取到的指令，**同时广播（fan-out）送入 4 个核心的取指（取值）端口**（4 核同拍收到同一条指令）。
  - 端到端：**全局 PC(`pc` 16bit) → `addr_in` → `g_raddr`(17bit,={0,addr_in}) → 内存取指 → `g_rdata`(32bit) → 取上 24 位(`g_rdata[31:8]`) → 广播到 4 核指令端口(24bit)**。
- **核心指令端口为 24bit**：连线方式 = 取读到的内存数据（`g_rdata` 32bit）的**上 24 位**，即 `instr = g_rdata >> 8`（等价 `g_rdata[31:8]`）。
  - 当前 `GpuSystem` 仍用内部 `imem[pc>>1]` 取指，本通道为后续接入预留，尚未接线。

> **具体存储实现（测试阶段）**见 `docs/memory/memory_module_spec.md`：64KB、16bit 字节地址、32bit 数据、4 组读写接口（含 2bit 字节使能小端）+ 1 个取指读接口。
- 内存侧由 `Memory`（或外部存储）为 4 组端口 + 副读通道提供读写。

## 6. 悬置项（不猜测）
- **寻址粒度**：17bit 地址按字节还是按 16bit/32bit 字 —— 暂不考虑。
- **副读通道用途**：已明确=预留连接全局 PC（取指地址）与核心取指端口（共享指令取指通道）；仅端口已定义，接线待后续。
- **原子操作**（ATADD/ATSWAP/ATCAS，含 ATCAS 的 cmp/new 端口）：本轮不纳入本接口，后续详细讨论再实现。
- **同地址冲突仲裁**（P0 原子 / P1 普通写 / P2 普通读 的同地址排队与可见性）—— 待协议展开。
- 栈协议（r15 栈基址的增长/回退、PUSH/POP 方向）—— 待展开。
