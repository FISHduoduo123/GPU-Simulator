# 全局内存控制器（Global Memory Controller）—— GPU 模拟器

> 一句话作用：GPU 顶层的全局内存控制器，统一管理全局内存，并向各 warp 提供内存访问接口。

- 模块：全局内存控制器（GPU 顶层）
- 状态：**设计中**（大方向已确认 2026-11-28；端口/仲裁细节待用户细说）
- 更新日期：2026-11-28
- 依据：用户确认（分支 `design/memory-decouple`）
- 关联：`docs/memory/memory_spec.md`、`docs/warp/warp_spec.md` §4、`docs/scheduler_spec.md`、`docs/open_items.md` D1

## 1 概述

- **2026-11-28 决定（分支 design/memory-decouple）**：把**整个统一内存与 warp 的连接断开**（取指 + 访存），内存上移到 **GPU 全局级**。
- 全局内存以 **GPU 顶层独立内存模块 + 全局内存控制器** 形式存在；**调度器只管 block→warp 槽位，不管内存**。
- 每个 warp 有一个 **warp 级内存控制接口**，用于连接全局内存控制器的接口。
- **取指按原先方式**：PC 仍在 warp 内，取指地址经 warp 内存控制接口发到全局内存控制器，指令数据再返回 warp 广播到 4 核（原 `g_raddr/g_rdata` 思路不变，只是隔着控制器）。

## 2 端口与接口（待细说）

- 全局内存控制器对外端口：待用户细说（仲裁策略也待细说）。
- warp 级内存控制接口（连控制器）：待细说。
- **栈请求输入（2026-11-28 已定）**：每核/每 warp 的 `stack_op`(2bit: 00无/01 PUSH/10 POP) + `stack_addr`(17bit = r15) + `stack_wdata`(16bit，仅 PUSH)；接到本控制器，由控制器内计数器完成栈寻址（见 §3.1）。

## 3 功能与行为

- 汇聚多个 warp 的取指/访存请求，访问全局内存。
- 仲裁策略：**待用户细说**（FIFO / 固定优先级 / 同拍单服务 等候选）。

### 3.1 栈（PUSH/POP）机制（2026-11-28 已定）
- 控制器内部维护一个 **16bit 计数器 `stack_ctr`**：初值 0，溢出/下溢回绕。
- **有效访存地址 = `stack_addr`(r15) + 计数器当前值**（用户确认：地址与计数器值相加）。
- **PUSH**（`stack_op=01`）：本拍以 `r15 + stack_ctr` 写入 `stack_wdata`；**下个周期上升沿** `stack_ctr <= stack_ctr + 1`。
- **POP**（`stack_op=10`）：**本拍组合逻辑**算出 `stack_ctr - 1`，以 `r15 + (stack_ctr - 1)` 读出（读返回送回核心写 f1 目的寄存器）；**下个周期上升沿** `stack_ctr <= stack_ctr - 1`。
- 即标准 LIFO：PUSH 写栈顶后上移，POP 读次栈顶后下移。

## 4 待确认 / 悬置

- 控制器端口列表/位宽/方向。
- warp 级内存控制接口的信号组成（是否拆成 取指子接口 + 访存子接口）。
- 多 warp 同拍仲裁与响应时序（单拍/多拍、握手）。
- 内存容量/地址空间是否仍为 64KB / 17bit 口径。

## 5 变更记录

- 2026-11-28：创建骨架。大方向确认：内存上移 GPU 全局级、warp 经 warp级内存控制接口连接全局内存控制器、取指按原方式、调度器不管内存；端口与仲裁待细说。
- 2026-11-28：新增栈请求输入端口（`stack_op`2/`stack_addr`17/`stack_wdata`16）与 §3.1 栈机制——控制器内 16bit 计数器（初0、回绕），有效地址=r15+计数器；PUSH 下拍上升沿 +1，POP 本拍组合 -1、下拍上升沿更新为 -1 值。
