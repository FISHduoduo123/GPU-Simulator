# BRU 内部逻辑设计 —— GPU 模拟器

- 项目：GPU 模拟器
- 模块：外部 **BRU（Branch Unit）内部判定/输出逻辑**
- 状态：**BRA 普通属性、BRAF 三状态收敛逻辑已确认；弹栈/收敛点等细节待用户继续完善；未写实现代码**
- 更新日期：2026-11-24
- 依据：用户规定（4 核共享 PC；BRA func 双属性；PC 顺延 +2；BRAF 三状态收敛栈）
- 关联：`docs/bru_interface_spec.md`（端口）、`docs/branch_interface_spec.md`（分支端口）

---

## 1. 前提（已确认）
- **4 个线程核心公用一个 PC**，天然锁同步，正常都执行同一地址。
- 输入：4 组 分支端口（`br_op`/`br_jump_addr`/`br_cond`/`br_uncond_attr`/`br_func`/`br_flags`）。
- 输出：`bru_jump_addr`(16bit 新 PC)、`bru_jump_req`(1bit)、`bru_en[3:0]`。

## 2. PC 推进（已确认）
- **PC 顺延恒 `+2`**：16bit 指令在 16bit 粒度寻址下占 **两个地址空间**，故下一指令地址 = PC+2。
- 发生**可取跳转**时：`bru_jump_req=1` 且 `PC ← 目标地址`（bru_jump_addr）；否则 `PC ← PC+2`。

## 3. BRA（op=0110）双属性
| BRA func | 属性 | 处理 |
|---|---|---|
| `0` | **普通属性**（无条件） | 直接取本组 `br_jump_addr` 作为跳转目标 → 发 `bru_jump_addr`、置 `bru_jump_req=1`、`PC=目标` |
| `1` | **收敛属性** | 收敛点处理见 §3.1 |

> **收敛属性由 BRA 指令本身的 `func=1` 判定，无需额外插入任何标记指令**。即：BRA 的 func 位 = 是否具有收敛属性；`func=0` 普通属性 → 直接设置 PC；`func=1` 收敛属性 → 走 §3.1 的收敛处理。收敛（when to merge）就发生在执行到该条的 BRA(func=1) 时。

### 3.1 BRA(func=1 收敛属性) 的收敛点处理（已确认）
- **在分支路径 1 状态**遇到 BRA(func=1)：
  1. 将 BRU 状态设置为 **2**（分支路径 2）；
  2. 修改**栈顶的状态字段**（1bit）为路径 2；
  3. 根据**栈里的地址**设置 PC（栈顶 16bit 地址）；
  4. 把**本条指令里的跳转地址**写入栈里**替换**（替换栈顶的 **16bit 地址字段**，用户已确认）。
- **在分支路径 2 状态**遇到 BRA(func=1)：
  1. **比较栈顶地址**与**指令里的地址**（比较结果**预留**，暂不定义其分支作用）；
  2. 把**栈中地址**设置给 PC；
  3. 再**弹栈**；
  4. 弹栈后 BRU 状态设置为**新栈顶里的状态**；若**没有栈块（00）**则回到**普通状态**。

## 4. BRAF（op=0111，分支类型指令）三状态收敛逻辑（已确认）
### 4.1 BRU 状态（共 3 种）
1. **普通状态**
2. **分支路径 1**
3. **分支路径 2**

### 4.2 处理流程（op 为 BRAF 时）
1. **先判断当前 BRU 状态**（普通 / 路径 1 / 路径 2）。
2. 根据 `cond` 码与**标志端口**比对：
   - **未被使能线程核心的标志输出被禁止**（即仅比对使能线程的标志）。
   - 记录**满足的线程**与**不满足的数量**。
   - **判定依据只取“当前使能的线程核心”**：未使能的核心不加入判断，也不影响下面的分类（**仅满足 / 仅不满足 / 混合** 都是相对于「当前使能核心集」而言）。
3. **分情况**：
   - **既有满足又有不满足（混合）**：
     1. **压栈**（BRU 维护一个栈），每个栈条目 = **1bit + 4bit + 16bit**：
        - `1bit`：当前分支路径 **1 或 2** 状态；
        - `4bit`：指向线程，**每位 = （该线程满足状况取反）AND 使能**，即 `~满足 & 使能` —— 记录**仍使能但未满足**（走另一路径）的线程掩码（用户 m00861/m00863 将**“或”改为“与”，且用“满足取反 再 and 使能”**；早前«满足 OR 使能»作废）；
        - `16bit`：**当前指令的下一条指令地址**。
     2. **设置使能端口 `bru_en`：只使能满足的线程**（未满足的线程禁能，其屏蔽信息保存在栈条目 4bit 中）；
     3. 将 BRU 变为 **分支路径 1** 状态；
     4. 将 **PC 设为满足分支的跳转地址**。
   - **只有一种情况**：
     - **满足**（全部满足）→ 直接设 **PC = 跳转地址**；
     - **不满足**（全部不满足）→ **不设置 PC 值**。
4. **分支路径 1 或 2 状态下**：操作与**普通状态相同**（同样比对 + 混合时压栈 + 转路径 1 + PC=满足跳转地址）。

## 5. CALL / RET 调用栈（已确认）
- BRU 另维护一个**独立的调用栈**：**深度 16，每项 16bit**（与 §4 收敛栈分开）。
- **CALL**（`br_op=1001` 且 `br_func=0`）：把 **PC+2** 压入调用栈（PC+2 = 当前指令的下一条指令地址），**同时把本条指令的目标地址（`br_jump_addr`）设置给 PC**。
- **RET**（`br_op=1001` 且 `br_func=1`）：从调用栈**弹出**一项，**设置为 PC**。
- 栈溢出/下溢处理、CALL/RET 是否影响使能/收敛状态 —— 待确认。

### 5A. BRAP / REA（已确认）
- **BRAP**（`br_op=1000` 且 `br_func=0`，内核入口）：
  - **读各核心掩码端口 `br_mask`**：若某核心掩码读到 `1`，则**关闭该核心的使能控制**（`bru_en[k]=0`）；掩码为 `0` 的核心保持使能。
  - 然后**设置 PC 值**（BRAP 目标 / 内核入口地址）。
  - **掩码寄存器的写入来源（已确认，随指令集更新）**：由核心执行 `MOV` 指令 `type=0111` 即 **`mask ← reg[0]`**（取源寄存器第 0 位写入掩码寄存器），随后经 `br_mask` 端口送到 BRU 供 BRAP 判定。
- **REA**（`br_op=1000` 且 `br_func=1`）：**使能控制端口全部使能**（`bru_en = 4'b1111`），**不设置 PC**（顺延）。

## 6. 综合流程（草稿）
1. 读取 4 组 `br_op`。
2. 每组按各自 op 分支：
   - `br_op=0000`：无分支 → 该核顺延。
   - `br_op=0110`（BRA）：按 §3 依 func 处理（func=1 收敛属性见 §3.1）。
   - `br_op=0111`（BRAF）：按 §4 三状态收敛逻辑处理。
   - `br_op=1001`（CALL/RET）：按 §5 调用栈处理。
   - `br_op=1000`（BRAP/REA）：按 §5A 处理。
3. 汇总：有可取跳转 → `bru_jump_req=1` + 目标 `bru_jump_addr`；否则请求=0 顺延 +2。
