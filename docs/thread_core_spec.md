# 线程核心（Thread Core）规格书 —— GPU 模拟器

- 项目：GPU 模拟器
- 模块：基础线程核心（指令译码控制 + ALU + FPU + 寄存器组）
- 状态：**接口规格已确认；已实现寄存器/计算类指令，流控与访存/原子待展开（见 §7 指令状态表）；实现代码待用户明确说“写代码”后编写**

- 依据：`docs/regfile_spec.md`、`docs/alu_spec.md`、`docs/fpu_spec.md`、`docs/branch_interface_spec.md`、`docs/mem_interface_spec.md` 及用户规定

## 1. 内部主要结构（已确认）
- **指令译码控制模块**（Decode & Control）：解析指令、调度执行、管理回写，内部持有寄存器组。
- **ALU**：`op=0100` 整数算数逻辑单元（`src/alu.rs` 的实现规格）。
- **FPU**：`op=0101` FP16 浮点单元（`src/fpu.rs` 的实现规格）。
- **寄存器组 RegFile**：16×16bit、4 读 1 写，作为**核心内部状态**，由指令译码控制模块读写；ALU/FPU 从读端口取源操作数，结果经译码控制模块回写。
- **掩码寄存器**：核心内部维护一个 **1bit 掩码寄存器**；其当前值经**掩码标志端口**输出给 BRU（存入 BRU 的收敛栈条目作为线程掩码）。
  - **写入来源（已确认，随指令集更新）**：指令 `MOV` 的 `type=0111` 执行 **`mask ← reg[0]`**，即取**源寄存器的第 0 位**写入掩码寄存器。MOV type 全表：`0000` reg⇔reg、`0001` reg←warp_thread_id、`0010` reg←warp_id、`0011` reg←block_x_id、`0100` reg←block_y_id、`0101` reg←grid_x_line、`0110` reg←grid_y_line、**`0111` mask←reg[0]**。

## 2. 对外接口（已确认）
| 端口 | 方向 | 位宽 | 说明 |
|---|---|---|---|
| 指令端口 | 输入 | 32bit | 待译码执行的一条指令（编码见 §3） |
| 使能端口 | 输入 | 1bit | `en=1` 读取并执行指令端口；`en=0` 视为 NOP |
| 计算标志端口 | 输出 | 16bit | 低 10bit 整数标志 + 高 6bit 浮点标志（见 §6） |
| 掩码标志端口 | 输出 | 1bit | 核心内 **1bit 掩码寄存器**的当前值，**输出给 BRU** |
| 分支端口 | 输出 | 见 §2.1 | 流控指令（BRA/BRAF/BRAP/REA/CALL/RET）送往外部 **BRU**（详见 `docs/branch_interface_spec.md`） |
| 访存接口 | 输入/输出 | （见 §5） | 访存指令（STR/LDR/原子等）的命令通道（详见 `docs/mem_interface_spec.md`），协议后续展开 |

### 2.1 分支端口（输出到 BRU，已确认，详见 `docs/branch_interface_spec.md`）
| 端口 | 位宽 | 说明 |
|---|---|---|
| `br_jump_addr` | 16bit | 跳转目标地址 |
| `br_op` | 4bit | 控制流 op：0000 无 / 0110 BRA / 0111 BRAF / 1000 BRAP·REA / 1001 CALL·RET |
| `br_cond` | 4bit | 条件编码 0..15（由 BRU 结合标志判定） |
| `br_uncond_attr` | 1bit | BRA 的 0/1 收敛属性位 |
| `br_func` | 1bit | 子类型：CALL/RET(0/1)、BRAP/REA(0/1) |
| `br_mask` | 1bit | 掩码寄存器当前值 |
> 无请求有效信号：BRU 以 `br_op != 0000` 判断本周期是否有分支请求。

> 时钟 `clk`（上升沿写回）、复位（异步，全 0）为核心内部公共信号。

## 3. 指令端口编码布局（已确认）
- 固定 **32bit，高位对齐**：`op[3:0] = bits[31:28]`，随后 7 个 4bit 字段：

| 位域 | bits | 含义（对大多数指令） |
|---|---|---|
| op | [31:28] | 操作码（0000..1111） |
| 字段1 | [27:24] | 目的寄存器 rx 等 |
| 字段2 | [23:20] | 源1 等 |
| 字段3 | [19:16] | 源2 等 |
| 字段4 | [15:12] | 源3 / 立即数 / 地址等 |
| 字段5 | [11:8] | func / meta / cond / 0-1 等 |
| 字段6 | [7:4] | 保留（默认 0） |
| 字段7 | [3:0] | 保留（默认 0） |

- 由表格第 5 行列出的映射：列 B=op，列 C=字段1，列 D=字段2，列 E=字段3，列 F=字段4，列 G=字段5（func/type/cond）。字段 6/7 为保留位。
- 同一 op 下各字段的具体语义按具体指令（如 MOV 的 type、BRA 的 addr、ALU 的 func）在相应执行单元规格中定义。

## 4. 指令周期（一个周期，已确认）
1. **取值**：`en=1` → 读指令端口；`en=0` → 内部视为 NOP。
2. **译码**：译码控制模块解析 op/func、目的寄存器号、源寄存器号、立即数、访存字段。
3. **读源**：组合地从寄存器组读端口取源操作数，送往对应执行单元（ALU 或 FPU，按 op 决定）。
4. **执行**：纯组合、单周期（ALU 或 FPU）。
5. **访存**：若为访存指令（op=1010），通过**访存接口**发起命令（协议见 §5，后续展开）。
6. **标志**：比较结果写入**计算标志端口**（见 §6）。
7. **写回**：结果经 WB MUX → 寄存器组写端口，在 `clk` 上升沿统一提交。

## 5. 访存接口（骨架，协议后续展开）
- 预留端口方向与字段（详细握手/队列协议在下一轮展开）：

| 信号（命名示意） | 方向 | 说明 |
|---|---|---|
| `mem_req_valid` | 输出 | 本次有访存请求 |

- 覆盖指令：STR、LDR、PUSH、POP、ATADD、ATSWAP、ATCAS（op=1010）。

## 6. 计算标志端口（已确认）
- **16bit 合并**：`flags[9:0]` = 10bit 整数标志（EQ/NE/LT/GT/LE/GE/ULT/UGT/ULE/UGE），`flags[15:10]` = 6bit 浮点标志（FEQ/FNE/FLT/FGT/FLE/FGE）。
- **每周期写入比较结果**：
  - 整数比较指令（ALU func=0001 SUB/CMP）：写入整数标志段并置有效。
  - 浮点比较指令（FPU func=0001 HSUB/CMP）：写入浮点标志段并置有效。
  - 非比较指令：对应标志段**保持前一拍值或清为无效**（可选 valid 位标识）。

## 7. 指令执行状态表（编码就绪视图）
| op | 指令 | 状态 |
|---|---|---|
| `0000` | NOP | 已实现 |
| `0001` | MOV（type 0000–0110 寄存器/线程坐标；**type 0111 → mask←reg[0]**） | 0000–0110 已实现；0111 掩码写入待实现 |
| `0010` | LDI（rx ← imm） | 已实现 |
| `0011` | SEL（rx ← cond? a : b） | 已实现 |
| `0100` | 整数 ALU（12 条，见 `docs/alu_spec.md`） | 已实现 |
| `0101` | FP16 FPU（见 `docs/fpu_spec.md`） | 已实现 |
| `0110` | BRA（普通/收敛，输出分支端口） | 规格已定（BRU 侧见 `docs/bru_logic_spec.md`）；核心译码待实现 |
| `0111` | BRAF（条件分支） | 同上 |
| `1000` | BRAP / REA（func 区分） | 同上 |
| `1001` | CALL / RET（func 区分） | 同上 |
| `1010` | 访存 STR/LDR/PUSH/POP/ATADD/ATSWAP/ATCAS | 骨架已留；地址/栈/响应/原子协议待展开（`docs/mem_interface_spec.md`） |
| `1011` | SYNC | 待实现（指令集备注：不允许在分支路径内加入全局栅栏，可能死锁） |
| `1100`–`1111` | HLT / HLTF / DONE / DONEF | 已实现 |

> 说明：上表中「已实现」指 `src/thread_core.rs` 已有对应处理；流控类 currently 仅产生分支端口/桩，最终由 BRU 决定跳转（见 `docs/bru_logic_spec.md`）。
