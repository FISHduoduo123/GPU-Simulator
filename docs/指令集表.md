## 1. 指令位布局（24bit，已确认）
一条 `24` 位指令 `I`：

| 位域 | bits | 对应 xlsx 列 | 通用含义 |
|---|---|---|---|
| op | `I[23:20]` | C | 操作码（0000..1111） |
| 字段1 | `I[19:16]` | D | 目的寄存器 / 分支地址等 |
| 字段2 | `I[15:12]` | E | 源1 / sed 立即数 / 数据等 |
| 字段3 | `I[11:8]` | F | 源2 / 基址等 |
| 字段4 | `I[7:4]` | G | 源3 / 偏移 / 新值等 |
| 字段5 | `I[3:0]` | H | func / type / cond / 0-1 属性 |

译码取字段：
- `op   = (I >> 20) & 0xF`
- `f_n  = (I >> (20 - 4n)) & 0xF`，n = 1..5

> 与旧 32bit 的差异仅在**位移**：旧 `op=I[31:28]`、`fld = I>>(28-4n)`；新 `op=I[23:20]`、`fld = I>>(20-4n)`。各字段的**语义角色不变**，只是编号位置整体下移 8 位。

**分支指令的地址**（用户确认：指令集中跳转地址均为 **16bit**）：BRA/BRAF/BRAP 的目标地址占 `f1..f4 = I[19:4]`（16bit），`f5=I[3:0]` 保留给 0/1 属性 / cond / func。即：
- `branch_addr = (I >> 4) & 0xFFFF`。

## 2. 各指令的字段语义（重排后不变，落 A1 用）
下表为译码时每个字段的语义角色（“-”=未用/忽略）。

| op | 指令 | f1(D) | f2(E) | f3(F) | f4(G) | f5(H) |
|---|---|---|---|---|---|---|
| 0000 | NOP | - | - | - | - | - |
| 0001 | MOV | rx(目的) | rx(源) | - | - | type |
| 0010 | LDI | rx(目的) | **imm 16bit（f2..f5 合为立即数）** | | | 0000 |
| 0011 | SEL | rx | rx | rx | - | cond |
| 0100 | 整数 ALU | rx(目的) | rx(a) | rx(b) | - | func |
| 0101 | FP16 FPU | rx(目的) | rx(a) | rx(b) | rx(c, 仅 HFMA) | func |
| 0110 | BRA | addr | - | - | - | 0/1 属性 |
| 0111 | BRAF | addr | - | - | - | cond |
| 1000 | BRAP | addr | - | - | - | 0000 |
| 1000 | REA | - | - | - | - | 0001 |
| 1001 | CALL | **addr 16bit（f1..f4）** | | | | **0（压栈）** |
| 1001 | RET | - | - | - | - | **1（出栈）** |
| 1010 | STR | - | rx(数据) | rx(基址) | rx(偏移) | 0000 |
| 1010 | LDR | rx(目的) | - | rx(基址) | rx(偏移) | 0001 |
| 1010 | PUSH | - | rx(待压值) | - | - | 0010 |
| 1010 | POP | rx(目的) | - | - | - | 0011 |
| 1010 | ATADD | rx(目的) | rx(值) | rx(基址) | rx(偏移) | 0100 |
| 1010 | ATSWAP | rx(目的) | rx(值) | rx(基址) | rx(偏移) | 0101 |
| 1010 | ATCAS | rx(目的) | rx(cmp) | rx(基址 res) | rx(new) | 0110 |
| 1011 | SYNC | - | - | - | - | - |
| 1100–1111 | HLT/HLTF/DONE/DONEF | - / - / - / - | - | - | - | cond(HLTF/DONEF) |

> 说明：PUSH/POP 的访存地址使用 **r15（栈基址寄存器）**，无基址/偏移字段；STR/LDR 及原子操作地址 = f3 基址寄存器 + f4 偏移。各条指令格式已于 **2026-11-25 由用户逐条确认**（本轮修正：LDI 立即数 16bit 占 f2..f5、CALL 带 16bit 地址而 RET 不带、ATSWAP 也带偏移、HLTF/DONEF 带 cond）。

### MOV type 子表（f5=H，2026-11-28 用户确认来源）

| type | 含义 | 取值来源（写入 rd=f1，16bit） |
|---|---|---|
| 0000 | reg ⇔ reg | 源寄存器 f2 的值 |
| 0001 | warp_thread_id | **线程二维编号**：x 存高 8 位、y 存低 8 位；4 线程 warp 中核 k(0..3) → `x=k>>1, y=k&1`，值=`(x<<8)\|y`（0x0000/0x0001/0x0100/0x0101），每核不同 |
| 0010 | warp_id | **warp 二维编号**（与 thread id 同样打包：x 高 8 位、y 低 8 位），warp 级输入端口，4 核共享同值；来源=该 warp 在 block 内的编号（调度器分配），暂无调度器时默认 (0,0)=0x0000 |
| 0011 | block_x_id | warp 外部输入端口 `block_x`(16)，4 核同值 |
| 0100 | block_y_id | warp 外部输入端口 `block_y`(16)，4 核同值 |
| 0101 | grid_x_line | warp 外部输入端口 `grid_x`(16)，4 核同值 |
| 0110 | grid_y_line | warp 外部输入端口 `grid_y`(16)，4 核同值 |
| 0111 | mask ← reg[0] | 源寄存器 f2 的第 0 位 → 1bit 掩码寄存器 |

## 3. 取指 / 装载 / PC 对齐（A1 范围内）
- **指令端口 24bit，直接译码**（用户确认）：核心收到的就是 24bit `I`，无需先 `>>8`。
- **仿真器内部 `imem`**：直接存 24bit 指令 `I`（如 `Vec<u32>`，值 < 2^24），`fetch()` 返回 `imem[pc>>1] & 0xFFFF_FFFF`（越界返回 0=NOP）；核心 24bit 端口直接用该值译码。
- **PC 步长**：`+2`（同 `docs/warp/pc_spec.md`），一拍一条指令。
- 说明：真实 64KB 字节内存的「指令跨两单元存放」（**大端**：低地址单元放高 16 位 `I[23:8]`、高地址单元放低 8 位 `I[7:0]`；取指端口交换上下 16 位重组后取高 24 位）属 **D2/A4 接线与内存模块**职责；仿真器内部 `imem` 以 24bit 直存作为桥接模型，不改变核心译码。

## 4. 所需代码改动清单（写代码时执行，现仅列出）
- `src/thread_core.rs`：
  - `fld(instr, n)`：位移 `28-4n` → `20-4n`；`op = (instr >> 20) & 0xF`。
  - `branch_addr(instr)`：改为 `(instr >> 4) & 0xFFFF`（16bit 地址占 f1..f4）。
  - 各 op 分支按 §2 复用字段取值（语义不变）。
- `src/system.rs`：
  - `enc(opc, fields) -> u32`：直接组 24bit `I = op<<20 | f1<<16 | f2<<12 | f3<<8 | f4<<4 | f5`（不左移 8）。
  - `fetch()`：返回 `imem[pc>>1]`（24bit 值；越界仍当 NOP=0）。
- `src/bru.rs`：`cond_satisfied` 走 `br_flags`，与位布局无关，**不改**。
- 测试：`enc` 新编码驱动下，既有 46 个测试（含 thread_core 译码类）需随位移重排核对；确保仍全绿。
